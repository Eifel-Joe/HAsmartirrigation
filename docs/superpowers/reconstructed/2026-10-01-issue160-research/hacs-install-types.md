# HACS: installation types, platforms, versions - installable, refused, or formally unsupported?

Research date: 2026-10-01. Read-only (no posts, comments, issues or other remote writes).
Question: is there ANY Home Assistant (HA) install variant, platform or version on which HACS cannot be installed,
is refused, or is formally unsupported - with the focus on "Home Assistant Container" (Docker) users of
Irrigation Plus (JustChr/HAsmartirrigation, `hacs.json` homeassistant 2025.5.0).

Sources actually read (all verified at the dates given):
- hacs/integration: full git history (2610 commits, HEAD adb7d83e, 2026-09-05), latest release 2.0.5 (2025-01-28; the HACS data feed
  data-v2.hacs.xyz still reports `last_version` 2.0.5 on 2026-09-30).
- hacs/documentation (hacs.xyz docs source): full history (745 commits, HEAD d8800f6, 2026-08-19).
- hacs/get (download script): full history (59 commits, HEAD ebc9d97, 2026-06-08). hacs/addons ("Get HACS" app): full history (48 commits, HEAD 9a6b3a3, 2026-08-24). hacs/frontend: GitHub code search only.
- HA side via `gh api`: home-assistant/architecture (ADRs), home-assistant.io (docs + blog), core (`system_info.py`, `loader.py`), supervisor (job conditions), analytics.
- GitHub issues in hacs/integration (read with `gh api`), HA Community threads (4 read as raw Discourse JSON, others only via search summaries - flagged).

Legend for column 2:
- yes = documented/observed to work.
- formally unsupported = outside HACS's stated prerequisite "a supported Home Assistant installation" (HA ADR-0012 definition: tested and documented by HA), but NOT blocked by any HACS code.
- no = refused by code (HACS, get script, Supervisor, HA loader) or technically impossible.

## 0. Bottom line

1. No HACS component (integration, get script, add-on, docs) has ever contained a check of the HA installation type, Supervisor/hassio presence, Docker/container, or CPU architecture (section 3, with negative-search commands).
2. Home Assistant Container is a first-class, documented HACS route (docs tab + CI matrix target "Container" in hacs/get since 2020-12-23) and, per HA ADR-0013, one of only two HA-supported install types (OS and Container) since 2025.12. Container users are a real population: 120,761 of 691,602 opt-in HA installs = 17.46 % (HA analytics, data of 2026-09-29), second only to OS (79.68 %).
3. The things that DO refuse or are formally unsupported are: HA older than the HACS minimum (2024.4.1 for the latest release 2.0.5), the single HA version 2023.12.0 (get script), Core and Supervised installs (formally unsupported by HA since 2025.12, but HACS docs still list them and nothing blocks them), Container variants that HA itself does not support (Windows/macOS/BSD hosts, 32-bit architectures, non-root or non-official images = HA label "Unsupported Third Party Container"), and environments where the script/files/GitHub are unreachable (read-only config dir, no GitHub access).
4. The sentence "HACS is only available for Home Assistant Operating System or Home Assistant Supervised installation method" is NOT in any HACS repository (full-history search: zero hits). A near-verbatim sentence exists on the official HA "Add-ons"/"Apps" page - about add-ons, not HACS (section 2).
5. Wording flag for JustChr/HAsmartirrigation#160 (2026-09-21; not edited, only observed): its text says "Routinely, on two officially supported install methods" and then lists Home Assistant Container (started without `-e TZ=`) and Home Assistant Core (in a venv on a server kept on UTC). As of 2026-10-01, "officially supported" holds for Container (ADR-0013, HA blog 2025-05-22, HA 2025.12) but NOT for Core: Core support was deprecated 2025-05-22, ended with release 2025.12, and ADR-0016 was reverted on 2026-04-02 (rows 10, 11 below). The same issue says OS and Supervised are unaffected; Supervised is likewise no longer supported.

## 2. Origin of the "only available for OS or Supervised" sentence

Not found in any HACS source. Searches (full history, all files, `git log --all -S`): terms "Supervised installation method" and "Operating System or" in hacs/integration, hacs/documentation, hacs/get, hacs/addons - zero hits. The HACS docs FAQ "Is this for hass.io only?" has answered "No" since 2019-11-02 (commit 8422374 in hacs/documentation).

Near-verbatim origin (high confidence for the wording, inference for the conflation): the official Home Assistant Add-ons page
(https://www.home-assistant.io/addons/, now https://www.home-assistant.io/apps/):
- 2018-02-15 (home-assistant.io commit 8746192d1): "Add-ons are only available if you've used the Hass.io installer."
- 2021-04-23 (commit 27519ec44, PR 17566 "Specify installation methods for add-ons"): "Add-ons are only available if you've used the Home Assistant Operating System or Home Assistant Supervised installation method." (rest: "If you installed Home Assistant using any other method then you cannot use add-ons.")
- 2026-01-22 (commit 674c3ffb4, PR 43220 "Remove docs about unsupported installation methods"): Supervised removed.
- 2026-02-11 (commit 24e2f0699, PR 43496): renamed to apps. Current page (read 2026-10-01): "Apps are only available if you used the Home Assistant Operating System installation method."
The subject is add-ons/apps. Apart from the subject (add-ons vs. HACS) and the paraphrased "if you've used" clause, the wording is the same as the claimed sentence; "installation method" is HA's fixed phrase, and "Supervised" in it dates such a snippet to 2021-04-23 .. 2026-01-22 (or a cached copy). HA docs use the same pattern in many Supervisor-only action pages (e.g. `source/_actions/hassio.host_reboot.markdown`: "only available when you run Home Assistant Operating System or the Supervised installation method"; not available on Container or Core).

Why a summarizer would attach it to HACS (inference, unverified): the HACS docs' only OS-specific route is an add-on, and several nearby HACS texts put "HACS", "add-ons" and "OS/Supervised" side by side:
- HACS docs FAQ "Apps?" (`source/docs/faq/addons.md`, introduced 2024-07-04, commit f7f06d5): "Get HACS add-on ... made for Home Assistant Operating System and Supervised to simplify the initial download of HACS itself." (today: "Get HACS app"). This is about the downloader add-on, not about HACS.
- HACS config flow acknowledgement (`translations/en.json`): "I know that there are no add-ons in HACS".
- HA blog 2024-08-21 (HACS 2.0 announcement): "it does not install add-ons".
- LinuxServer docker-mod README: "HACS does not contain add-ons, as add-ons are docker container based and are only supported in Home Assistant OS/Supervised."
- Name collision: "Home Assistant Community Add-ons" (hassio-addons) is a different project; HACS explicitly refuses such repositories (`exceptions.py`: "The repository does not seem to be an integration, but an app repository. HACS does not manage apps.").
Precedent that AI answers about HACS can be flatly wrong: the 2026-06-17 thread in row 19.

The thread the sentence was supposedly cited from was not given to me; I cannot confirm what it contains. Of the community threads I read as raw JSON (738493, 895475, 555899, 1014206), none contains the sentence.
